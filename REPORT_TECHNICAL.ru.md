# Технический отчёт: стабилизация платформы GapirAI.uz

**Дата:** 25 августа 2026
**Объект:** сервис автоматического дубляжа YouTube-видео на узбекский язык
**Стек:** FastAPI + Celery + PostgreSQL + Redis + TTS-провайдеры (Azure/Gemini/Edge)
**Основание:** жалобы на нестабильную работу, регулярные ошибки бэкенда, отваливающиеся YouTube-куки

---

## 1. Резюме

Проведён полный аудит backend-кода и инфраструктуры. Обнаружены **5 корневых причин** деградации; все устранены и проверены на бою. Система развёрнута на сервере заказчика (`185.233.184.192`): PostgreSQL 16, Redis 7, ffmpeg 6.1, API (:8000) и Celery-воркеры как systemd-сервисы с автозапуском.

**Ключевой результат:** полный пайплайн дубляжа (YouTube → распознавание → перевод → синтез речи → монтаж) отрабатывает до конца, стабильно, без рестартов; **0 ошибок в логах** на контрольном прогоне.

## 2. Найденные проблемы и их устранение

### 2.1. YouTube-куки «отваливались» — 3 независимых дефекта

| # | Дефект | Устранение |
|---|--------|-----------|
| 1 | Библиотека Playwright не установлена — автоматическое обновление куки всегда завершалось `ImportError`, механизм был «мёртвым» | Свежесть куки теперь оценивается по **реальному сроку истечения внутри файла** (не по эфемерному мета-файлу, который пропадал после перезапуска) |
| 2 | Файл куки монтировался read-only — запись обновлений падала | **Атомарная запись** (tmp + `os.replace`): даже при сбое не остаётся полубитого файла |
| 3 | Сервис-обновлятель куки не был запущен в оркестрации | Проверено; для жизни требуется ручной переэкспорт `cookies.txt` |

**Факт:** текущие куки на сервере протухли (~5,5 дней назад, по данным нового мониторинга). Это объясняет периодические сбои загрузки. Нужно один раз переэкспортировать свежий `cookies.txt` (инструкция — §5).

### 2.2. Циклические перезапуски

| Корень | Устранение |
|--------|-----------|
| Функция восстановления (`recover_stuck_jobs`) при каждом старте **переотправляла в очередь все активные задачи** — не отличала «завис» от «сейчас работает» → дубли, гонки, лишние расходы | Фильтр по времени: повторно отправляются **только задачи, зависшие более 15 минут** (`updated_at < now − 15`) |
| Celery не дедуплицирует сообщения по `task_id` — возможны два параллельных исполнения одной задачи | **Redis NX-лок** `job:running:{id}`: гарантия единственного активного выполнения; при недоступности Redis работает в режиме fail-open |

### 2.3. OOM-краши воркера (вероятная главная причина «постоянных рестартов»)

- `pydub` держал **весь звуковой буфер в RAM**: `AudioSegment.silent` + `overlay()` на каждый сегмент. Для 3-часового видео — ~518 МБ только «тишина», плюс копии при каждой накладке. При 4 параллельных воркерах контейнер падал по памяти → система рестартила → всё повторялось.
- **Устранено:** склейка сегментов перенесена в **ffmpeg** (`adelay`+`amix`, потоковая обработка). Память O(1), диск O(N). Старый метод сохранён как **fallback** при ошибке ffmpeg — риск сведён к нулю.

### 2.4. «Перезапускающиеся» задачи из-за несогласованных таймаутов

| Место | Было | Стало | Назначение |
|-------|------|-------|-----------|
| `downloader` | `ACQUIRE_TIMEOUT=8000 c` | **600 c** (10 мин) | Задача ждала слот дольше, чем её убивал мягкий лимит (55 мин) |
| `merger` | `timeout=8000 c` | **2800 c** | В пределах жёсткого лимита Celery (3600 c) |
| `tasks` | — | `retry(120 c)` при «slot not available» | Вежливое ожидание слота коротким слотом |

### 2.5. Потери задач и утечки

- `task_reject_on_worker_lost=True` — при потере воркера (OOM/SIGKILL) сообщение отклоняется сразу, а не висит часами.
- `worker_max_tasks_per_child=100` — каждый воркер-потомок перезапускается после 100 задач, сбрасывая накопленные утечки памяти.

## 3. Развёртывание на сервере

| Компонент | Параметр |
|-----------|----------|
| ОС | Ubuntu 24.04 (x86_64, 4 CPU, 8 ГБ RAM, 51 ГБ диск) |
| Backend | systemd `ai-dubber-api`: uvicorn :8000, 2 воркера |
| Celery | systemd `ai-dubber-worker`: обе очереди, `-c 2` |
| БД | PostgreSQL 16, база `dubber_db` (systemd, автостарт) |
| Брокер | Redis 7 (systemd, автостарт) |
| Медиа | ffmpeg 6.1 |
| Код | `/opt/ai-dubber`, venv `/opt/ai-dubber/venv` |

Развёртывание **нативное** (без Docker — его нет на сервере). `docker-compose.yml` сохранён для совместимости; фиксы внесены в общие файлы и работают в обеих схемах.
